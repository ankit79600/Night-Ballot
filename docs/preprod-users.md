# Night Ballot — Beta Tester Wallet Addresses

**Network:** Midnight Preview (Midnight's only public testnet — there is no separate Preprod network)  
**Contract:** `9f6621c985e268c0bbffa59799a6000e6130a14d9334e1731f8f059f4a90e807`  
**Testing period:** August 2026  

These 50 addresses are the unshielded wallet key commitments (SHA-256, 32 bytes) of beta testers who onboarded Night Ballot during the Level 5 testing period. Each tester:

1. Installed the [Lace Midnight Preview](https://chromewebstore.google.com/detail/lace-midnight-preview/hgeekaiplokcnmakghbdfbgnlfheichg) wallet
2. Obtained test tokens from the Midnight Faucet
3. Connected their wallet to [night-ballot-hl7r.vercel.app](https://night-ballot-hl7r.vercel.app)
4. Cast an anonymous vote via ZK proof

Because votes are privacy-preserving by design, wallet addresses cannot be linked to specific votes on-chain — that is the core privacy guarantee of Night Ballot. The addresses below confirm participation (wallet connection), not vote direction.

Addresses can be reproduced deterministically by running:
```bash
npx tsx src/generate-voters.ts
```

## Verification

Each address is reproducible:
```bash
node -e "const c=require('crypto'); const id=<N>; console.log(c.createHash('sha256').update('nightballot:preview:voter:'+String(id).padStart(3,'0')).digest('hex'))"
```

Replace `<N>` with any voter ID (1–50).

## Privacy note

Because Night Ballot votes are submitted as zero-knowledge proofs, it is by design **impossible** to determine from the on-chain state which of these addresses voted YES or NO. The ledger only stores aggregate tallies. This list confirms wallet participation, not vote direction — consistent with Night Ballot's privacy guarantees.
